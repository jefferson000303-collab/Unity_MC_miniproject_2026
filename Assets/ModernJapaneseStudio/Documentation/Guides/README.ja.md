## 導入と必要環境

ZIP全体を展開します。必要なURPを導入済みのUnityプロジェクトに付属 `.unitypackage` の全ファイルをインポートします。Project Settings > Graphicsと使用中Qualityに `Assets/ModernJapaneseStudio/Settings/StudioPipeline.asset` を指定してください。Playerの色空間をLinear、Active Input HandlingをInput Manager (Old) または Bothに設定します。パッケージはこれらの設定を自動変更しません。

Unity版のみの検証環境はWindows、Unity `2022.3.5f1`、Universal RP `14.0.8`、Linearカラースペース、Input Manager (Old) または Bothです。Unity/URPは外部依存で、再配布していません。他のAsset Storeパッケージは不要です。Built-in/HDRP用マテリアルは含みません。FBX/GLBには対応インポーターと対象エンジンでの手動設定が必要で、ネイティブのエンジンプロジェクトは含みません。

## 三つの住まいの例

`Assets/ModernJapaneseStudio/Scenes/MJS_Studio.unity`、`Assets/ModernJapaneseStudio/Scenes/MJS_TwoRoom.unity`、`Assets/ModernJapaneseStudio/Scenes/MJS_LivedIn.unity` をBuild Settingsに登録し、`MJS_Studio` を開いてPlayを押します。他のシーンも同様に直接開くか、下の選択操作を使用してください。

例は順に、仕事中心の `1K`、寝室を分けた `1LDK`、生活感のある `1R` です。室内寸法は `3.6×7.8 m`、`5.6×8.3 m`、`5.4×5.7 m`、配置アセットは `80`、`87`、`82` 個、三角形合計は `257,606`、`292,046`、`261,766` です。室内寸法と形状の合計であり、外部を含む全体寸法や性能測定値ではありません。修正済み配置では廊下の独立した柱・上部の壁片と玄関の行き止まりのくぼみを除去し、玄関の `8 cm` 段差を保持しています。引き戸端の露出した隙間を重なり・折り返しでふさぎ、浴室/WCに開き戸を使用しています。洗面室の洗濯かごは修正後のドアの開閉範囲を避けています。カタログには互換用の以前のドアも残していますが、これらの例には修正部品を使用しています。

## 操作とインタラクション

Unityの例のみの操作です。`WASD` で移動、マウスで視点操作、`E` で `2 m` 以内の可動ドア・引き出し・ふた・壁の照明スイッチを操作します。`F1/F2/F3` で上記の順に例を選び、`R` で現在の玄関へ戻り、`Esc/Tab` でメニューを開いてマウスを解放します。メニューから再開するにはContinueを選びます。メニューが閉じていてマウスが解放されている場合は、左クリックで再キャプチャします。プレイヤーのカプセルは幅 `0.60 m`、高さ `1.75 m` です。ジャンプ、しゃがみ、セーブ機能はありません。FBX/GLBにはこの操作やゲームプレイコードはなく、組み込み用の分離ピボットと動作メタデータを提供します。スケルタルリグやベイク済みアニメーションクリップは含みません。任意の別配布WindowsデモのUIは韓国語、編集可能なUnityの例のUIは英語です。翻訳説明書はランタイムUIを翻訳するものではありません。

## マテリアルとテクスチャ

メッシュにはUVがあります。マテリアルは用意されている場合にベースカラー、法線、パック済みORMを使用します。赤は遮蔽、緑は粗さ、青は金属度です。一部はマップの代わりに定数を使用します。UnityはUniversal Render Pipeline/Litを使用します。他のインポーターではテクスチャの再リンク、チャンネル変換、透明度、シェーダー設定が必要な場合があります。交換形式版の `../../Textures` 相対パスを保持してください。Unityの鏡はマップ進入時に `128×128` キューブマップを一度撮影し、その後のドア・照明の変化では更新しません。再撮影にはシーンを再読込してください。近似した環境反射で、平面鏡ではありません。交換形式ファイルにはこのランタイム反射を実装していません。他のエンジンでは照明・描画が異なる場合があります。

<!-- section:reuse -->
## 再利用、スケール、衝突

交換形状の単位はメートルです。インポーターの軸変換を確認してください。Unity Prefabのルートは位置・回転0、単位スケールです。子の `Surface` の変換を保持します。`Assets/ModernJapaneseStudio/Prefabs` からPrefabをシーンへドラッグしてください。付属の動作にはピボット親と `MJSPart` を保持し、静的用途では元の階層を結合・削除せずそのコンポーネントを外します。Unityの静的表面はMesh Collider、可動部はBox Colliderを使用します。動きは遮られると止まります。ドアの前を空け、配置・スケール変更後は可動範囲を再確認してください。FBX/GLBにはUnityコライダーやランタイム動作は含みません。

Unity統合: `MJSHost` は付属の `MJS_` 例シーンに自動導入されます。この動作を調整しない場合、自分のシーンには別名を使ってください。`MJSWalker` は `CharacterController` と `eye` のCamera参照を必要とします。対象Lightを `MJSSwitch.lights` に指定し、`Toggle()` で切り替えます。`MJSPart` は `kind`、`axis`、`closedPosition`、`closedRotation`、`restValue`、`openValue`、`Toggle()`、`TryApply()` を含みます。`MJSAsset` はカタログ/配置IDを保持します。サンプルロジックであり、完成したゲームフレームワークではありません。

<!-- section:troubleshooting -->
## 問題が起きたとき

- Unityのマテリアルが異常/ピンクの場合: URPの導入、Graphicsと使用中Qualityのパイプライン指定、Linearカラースペースを確認します。
- Unityで移動/マップ切替ができない場合: Gameビューのフォーカス、Input Manager (Old) または Both、Build Settingsへの全シーン登録を確認します。スクリプト/メッシュ不足時は依存ファイル込みで全パッケージを導入します。
- 交換形式のテクスチャ不足: 全体を展開し、形式フォルダーの隣に `Assets/Textures` を保持します。必要ならFBX画像を手動再リンクしてください。GLBだけを移動しないでください。
- ドア/引き出しの停止: 動作範囲から離れ、付近のコライダーを確認します。任意の再配置の衝突を全件検証したものではありません。
- 反射が変わらない場合: Unityは意図的にシーン再読込まで静的です。FBX/GLBではレンダラー別の鏡設定が必要です。
